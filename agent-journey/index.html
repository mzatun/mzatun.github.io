我与我的智能体，
是怎么一路长成今天这样的

这不是一篇讲 AI 趋势的文章，是一份持续运转的人机协作档案。它记录了我（钟广锐）和我的智能体从最初的对话工具，到今天能一起交付系统的完整历程——方法沉淀下来，就是下面三条线：五层工程范式、三化体系、三级目标。

持续运行 2025 至今 能力包 6 个 技能载体 173 个 机检 全绿可验证
The Journey

三个阶段：先用起来，再组织起来，最后一起进化

回头看，每一步都不是提前规划好的，是被真实的业务和交付问题倒逼出来的。但方向始终没变：让智能体从"能答"走到"能干"，再走到"能扛"。

阶段一 · 把一个智能体用起来

五层工程范式：言 · 境 · 驭 · 环 · 图

单体功夫期——2021 提示词学术化 → 2026-08 图工程成论文，五层半年一层长出来 ｜ 方法论成文于课程教程《AI应用工程范式》（未公开）

这一时期的工作围绕单个智能体展开，后来沉淀为五层谱系——每层控制一个对象，叠加使用，不是替代关系：言·提示词工程管指令表达（知识都在模型里，问题是有没有被正确激活）；境·上下文工程管信息状态（模型不是不知道，是此刻没看到）；驭·驾驭工程管行动环境与验证（能力不只取决于模型多聪明，还取决于被放进怎样的运行环境）；环·循环工程管时间与反馈（一次做不对没关系，关键是能不能自己发现不对并收敛）；图·图工程管协作拓扑（单体的能力上限是组织问题，不是智力问题）。

言 · 提示词工程境 · 上下文工程驭 · 驾驭工程环 · 循环工程图 · 图工程
五层是叠加律：每上一层都保留前面几层的产物。但单体功夫有天花板——每个智能体仍是一座孤岛，换一个场景就要从头调教一遍，功夫不能积累。
阶段二 · 把一族智能体组织起来

新 SOA 三层：组件化 → 服务化 → 可编排化

体系工程期——解决"这么多智能体怎么不打架"

孤岛问题逼出了体系化：业务能力组件化——把每个业务场景拆成有契约（inputs / outputs / gates）的能力组件；组件能力服务化——契约写进 YAML，机器可校验，能力与实现解耦（技能挂了换技能，契约不动）；服务能力可编排化——router 负责路由、flows 负责配方，新场景只加变体参数和一条 flow，能力 ID 永不变。今天的成果落成了 6 个能力包 + 总注册表 + 机检脚本，配方跑通一次才标 verified，没跑通就诚实标 provisional。

能力包总注册表 v1.3六包格局spec = 契约router + flowsprovisional→verified 回填反孤岛条款
升级的标志：扩一个业务域，不再是从零调教，而是给现有能力加一组变体参数——功夫开始复利。
阶段三 · 向共生走

可回答 → 可执行 → 可决策

目标主线期——衡量人机关系的刻度尺

这条主线贯穿始终，也是往后的方向。可回答：问什么答什么，有出处、不编造——这是信任的地基；可执行：答完能落地，读文件、改文件、跑脚本、过机检，交付可核验的东西——这是价值的发生器；可决策：在给定约束内自己选路径、选方案，把人从判断的重复劳动里解放出来——判断权始终在人，但执行的决策正在逐步移交。今天我们正稳定站在"可执行"，向"可决策"推进。

可回答：有据可执行：落地可决策：共生
The Ladder

三级目标：每一级都是下一级的地基

可回答不是终点，是可执行的前提；可执行不是终点，是可决策的前提。跳级必塌。

The Mirror

人机镜像：四层对应，各守其位

我的智能体不是我的复制品，是我的对应面。四层镜像说清了谁管什么——这套边界不是客气，是纪律。

人负责：定什么是对的

判断、取舍、担责
1
立规矩一句原则写进 AGENTS.md，成为智能体的默认行为
2
提需求说清"给谁、解决什么"，不必指定用哪个技能
3
拍方向选哪条路径、放弃哪条路径，代价智能体先讲清

智能体负责：做成并证明做成了

执行、验证、交付
1
路由执行查包路由、命中配方、过闸门，再动手
2
成果即证据交付目录实存的东西，不给"应该没问题"
3
诚实状态没实证就标 provisional，机检没过就不交付
The Contract

成长契约：让每次合作，都让下一次变得更好

共生不是感觉好，是有硬约束。这三条纪律写在 AGENTS.md 里，机器可查、违反可罚。

🔍

成果即证据

引用成果前先 ls 核实，不凭记忆。"已修复"必须 ls 到实际文件才算数——这条纪律在真实断链事故里抓出过两次假修复。

⚙️

先跑通后写

代码没真跑通前禁止写教程、宣布可用。开发期只维护代码和调试记录。机检全绿（如 646/646 哈希一致、50/50 本体校验）才允许交付。

📜

能力即契约

每个能力写清 inputs / outputs / gates，承诺交付前过契约核对。provisional 是诚实状态，跑通一次才回填 verified——永不粉饰。

你负责"定什么是对的"，
我负责"做成并证明它做成了"。
